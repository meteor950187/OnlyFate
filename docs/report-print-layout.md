# 報告內容與螢幕／PDF 編排

2026-11-04，維持六頁安排，依家長選名的任務調整說明量與間距。方向只在八字頁完整解釋；方案頁保留足夠的選字依據，挑字頁善用頁面高度，不以大量刪文代替閱讀設計。

1. 三步閱讀導覽、出生資料與姓氏、一句取名方向、兩方案風格標題及頁碼。四柱與完整判讀集中到第二頁。
2. 推薦前八字分析：先介紹日主及已有支援，再解釋出生季節、水的作用如何影響取名方向；每段包含條件的白話意思及對本次提案的關聯，避免只留下術語。四柱、取名方向與原有試行限制均保留，不新增人生預測。
3. 方案一：主推先說兩個字各自的心意及整體推薦理由。選字區說明五行安排，並以字池中的實際例字解釋寓意；四個搭配示例各有兩字風格與一句推薦理由。完整字典說明放在下一頁。
4. 方案一挑字：左右兩欄含完整讀音、本義、祝願、風格及留意，同頁交叉比較。內文11pt、行高1.65，字卡內距及卡片間距沿用v10。主推姓名改為右上角墨綠底淺字標示，組名與操作提示維持簡短。
5. 方案二：相同結構但明確不同的用字安排、風格及主推理由，不只換標題。
6. 方案二挑字：與第四頁相同的完整交叉比較。

兩方案共用已選的八字方向；依真實字池分類說明第一／第二字安排，依字庫profile與既有推薦短文說明寓意，不新增喜用推論或聲稱字序會帶來人生效果。林姓案例方案一土→金，偏寬厚堅定；方案二金→土，偏珍惜清朗。正常流程也從同一份ReportData生成，不硬寫林姓／特定字。

版型v12由`ReportHtmlRenderer.Content.cs`產生一份共用內容，`Screen.cs`與`Print.cs`分別控制螢幕和列印樣式；不新增模型呼叫、不變更計算與交叉配對規則。舊產物保留。示例wish仍保存於ReportData，兩種呈現皆以reason為整體推薦理由，再以固定字庫profile補足具體說明。選字區引用兩個非主推例字的namingWish；替代示例列兩字style。沒有新寫字典事實，也不使用截字或縮小內文來塞進六頁。

螢幕版沿用上述內容順序與視覺層級，段落自然延伸，不模擬固定紙張高度。首頁及方案末提供本頁錨點導覽，取代螢幕上無意義的PDF頁碼；寬視窗以雙欄比較第一字／第二字，620px以下改單欄並逐卡標示位置。內文16px、行高1.85，字卡完整顯示，不截斷長字義；兩組主推姓名均有墨綠底淺字標示。WPF只放行目前報告網址及其fragment，不放行其他案件、query或外部網址；JavaScript仍停用。

視覺層級：內文深灰（#454B50），標題及姓名墨綠（#173F36）；小標改黑體粗字，方案的兩個主要小節加短金色左線，次要風格標籤改灰色。金色用於導覽及輔助標籤，避免正文與標題都以相同墨綠顯示。

八字補文以既有案例研究與原判讀為依據，並核對[五行關係](https://wiki.openfate.ai/zh-hant/bazi/five-elements)、[日主與四柱](https://wiki.openfate.ai/zh-hant/bazi/four-pillars)、[取用方法](https://wiki.openfate.ai/zh-hant/bazi/useful-gods-climate)的傳統術語。涉及午月與庚金的說明須同時具有兩項引用事實；夏季與壬水同理。土金白話補充只在原方向已使用「土生金、金助金」且選字元素相符時顯示。這些是既有試行判讀的文字解釋，不把工具排盤當成已證實的取用結論。

驗收要求：林姓樣本實際WebView2列印為6頁並逐頁檢查；64個profile欄位在第4／6頁完整，10個姓名與推薦理由在第3／5頁完整。取名方向與適用限制集中在第2頁，第一頁閱讀提示同步頁碼。長文字/5字池可自然續頁，不裁切硬塞；6頁以本次實印樣本為範圍。實測證據見[驗收紀錄](acceptance.md)。
