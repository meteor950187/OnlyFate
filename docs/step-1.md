# Step 1：案件輸入與整理

狀態：輸入表單、國曆轉農曆及 SQLite 案件新增／儲存／重新開啟已實作。2026-11-02 修正約定：本步不呼叫 AI 整理備註或確認需求；備註原文留給後續判讀／選名使用。出生城市及時區在 [Step 2](step-2.md) 處理，本步不排盤、選名或寫報告。

## 輸入

目前案例範圍為單字姓、兩字名、國語讀音；其他姓氏型態或語言尚未驗證，不默認支援。

| 欄位 | 必填／選填 | 用途與處理 |
| --- | --- | --- |
| 姓氏 | 必填 | 保留原字，不由模型猜測或改字 |
| 性別 | 必填 | 男／女，供後續排盤與需求整理 |
| 國曆出生日期 | 必填 | 西元年月日；不提供國曆／農曆切換或閏月欄位 |
| 出生時間 | 必填 | 當地 24 小時制時、分；不預設時間，未提供秒數保持未知 |
| 出生地 | 必填 | 國家／地區與城市，供時區及地理資料解析 |
| 詳細地點 | 選填 | 醫院、地址或地標；保留供後續精確定位，此版尚未解析 |
| 避諱字 | 選填 | 明確禁止的用字；有填時須選「只避同字」或「同字與同音字」 |
| 指定字／輩分字 | 選填 | 有填時指定名首、名末或不限位置 |
| 需求與期望 | 選填 | 名字寓意、風格、辨讀偏好與其他彈性敘述 |

避諱字 placeholder：

> 例如：宏、志。若希望避開父母或長輩名字中的同音字，也請填入對應字，並選擇「同字與同音字」。

常駐說明：只需填入希望避開的字，不必提供父母或長輩完整姓名。

同音暫按國語相同讀音且同聲調處理；多音字若實際影響限制，再針對讀音補問。不收父母八字或以父母生肖進行相合判斷。

選填空白記為「未提供」，不自動解讀為「已確認沒有」。明確避諱字與指定字以制式欄位為準；不因備註資訊不足另外啟動 AI 補問。

## 程式負責的處理

- 驗證必填與條件式欄位；缺少必要出生資料仍須修正，不因省略備註整理就自行補值。
- 由原始當地國曆日期換算農曆與閏月，保留來源與計算基準。
- 保存表單明確限制、原始備註與輸入版本。
- 本步沒有模型呼叫、模型輸出或需求確認迴圈。

農曆生日以原始當地國曆日期換算，與後續真太陽時可能跨日的排盤日期分開。

「希望有志氣」與「避用志」分別是寓意偏好和禁字，不能直接判成衝突。

## 備註的後續使用約定

1. 輸入時逐字保存，包含換行，不先摘要或改寫。
2. 在後續判讀／選名的同一次模型任務中，將原文標為「補充資料」，由該步判斷是否適用；不增加前置整理呼叫。
3. 可處理的內容才採用，並記錄對應原文與用途。只適合選名的風格偏好留待選名處理，不拿來改變命盤取用。
4. 無法處理、資料不足或與制式欄位衝突的部分可以不採用；簡短記錄原因供商家查看，不另啟動 AI 問答迴圈，也不因單純未採用備註而阻擋流程。
5. 制式欄位及工具計算優先；備註不能覆寫生日、命盤、避諱字等明確資料，也不能當作變更系統規則的指令。

例如「希望有志氣」可以作為寓意偏好；不能自行變成必須使用「志」字。若備註要求避開長輩同音字但沒有提供對應字，可記錄「未採用：缺少對應字」，不猜長輩姓名。

備註的採用紀錄屬後續處理結果，不回寫原文。後續 context 的建議見 [Step 3](step-3.md)；目前尚未實作其模型呼叫。

## 最後輸出與完成條件

| 輸出 | 內容 |
| --- | --- |
| 案件基本資料 | 姓氏、性別、原始國曆出生日期、當地時間及精度、出生地 |
| 衍生曆法資料 | 農曆年月日、閏月、換算來源與基準 |
| 明確限制 | 避諱字與模式、指定字及位置；區分未提供與明確沒有 |
| 補充資料 | 備註原文；本步不產生已整理的偏好或已確認需求 |
| 追溯資料 | 原始表單、備註與輸入版本 |
| 待處理事項 | 必填或條件式欄位缺漏及格式問題，不把未整理備註列為必要待辦 |
| 案件狀態 | 資料就緒／等待補充／輸入需修正 |

必填有效、曆法換算成功，且該步必要的系統檢查完成，才算資料就緒。選填空白、未整理或未採用備註不自行阻擋；出生地是否足以排盤仍由 Step 2 檢查。

處理順序：表單驗證 → 曆法換算 → 原文與制式欄位儲存。輸入不符時由表單提示修正；沒有本步 AI 補問流程。

林姓虛構案例的國曆 2026-06-15 對應農曆五月初一、非閏月；原始實測見 [研究入口](research/README.md)。本步資料就緒不等同後續命理方法已驗證。

## 目前實作邊界與操作

- 「新增案件」開啟空表單，不預填姓氏、性別、出生日期、時分或地點，也不立刻寫入空案件。
- 「儲存案件」檢查所有必填與條件式欄位。缺漏或格式不符時顯示提示，保留輸入且不產生半份案件。DB 仍可保存 NULL，但本輪 UI 不提供不完整草稿儲存。
- 國家／城市下拉是可自行輸入的提示選項；不假定城市文字已驗證。城市候選確認、經度及歷史時區另由 Step 2 處理，詳見其規格。
- 農曆使用 .NET `ChineseLunisolarCalendar`，不需要 API、MCP 或使用者輸入閏月。閏月的 ordinal month 會正確轉為一般月份及閏月旗標；原始民用生日不因時間或時區換日。超出函式庫支援日期時顯示範圍並阻止儲存，不猜測結果。[官方說明](https://learn.microsoft.com/en-us/dotnet/api/system.globalization.chineselunisolarcalendar?view=net-10.0)
- 可明確勾選「已確認沒有避諱字／指定字」，與空白的「未提供」分開保存；勾選時清空對應的互斥輸入。這不要求提供家族完整姓名。
- 備註逐字保存，包括換行與引號；目前沒有 AI，也不解析同音字或實作選字。後續備註採用／未採用紀錄尚未實作。
- 案件主檔與第一版表單在同一個交易寫入。再次儲存修改會追加 CaseRevision，保留前版。若另一個視窗已更新案件，舊版本儲存會被拒絕，表單不自動覆蓋或清空。
- 重新開啟讀取最新版本的原始表單；切換到新案件、開啟其他案件或關閉時，若有未儲存變更先確認。日期尚在輸入、未失焦的文字也納入判斷。
- 現有程式儲存後仍為 `needs_input`；OrganizedContextJson、BirthTimeZoneID、ValidatedAtUtc 保持 NULL。Step 2 地點及時區收據保存於當次 run，不回寫原始版本。
- 2026-11-03 已移除新案件版本的 `remarks_interpretation_pending`；既有歷史版本不改寫，Step 3 不將此舊標記視為備註整理前置條件。

資料庫不需要變更 schema，舊 migration 保持原樣。共用案件存取放在 [CaseRepository](../src/OnlyFate.Database/CaseRepository.cs)，桌面表單放在 [CaseInputView](../src/OnlyFate.Desktop/Views/CaseInputView.xaml)。

測試包含表單→SQLite→重新開啟的資料往返。最新數量及範圍統一見 [測試入口](../tests/README.md)；未對新版執行 GUI／E2E 操作或視覺驗收，亦未將測試案件寫入正式 DB。啟用與建置入口見 [桌面 README](../src/OnlyFate.Desktop/README.md)。
