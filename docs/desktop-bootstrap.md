# 桌面初始化紀錄

日期：2026-11-02。使用者已確認 C#／WPF＋WebView2，並授權建立可啟動骨架。

## 範圍與完成條件

1. 同步技術決策與 Agent 規則，兩份 Agent 入口保持逐位元組一致。
2. 建立單一桌面專案、solution、SDK 選擇與 NuGet 相依鎖定；不預建服務層、測試空殼或資料表。
3. 主視窗可啟動，WebView2 載入隨程式附帶的本機 HTML 空白預覽；不啟動 HTTP server。
4. 預覽載入失敗時，主視窗仍保留可讀提示；WebView2 使用者資料位於本機應用程式資料夾，不寫入原始碼目錄。
5. 執行還原、建置與實際視窗驗證，確認正常顯示及關閉後可再次開啟，最後補上已驗證操作入口。

本輪不串 OpenAI API、OpenFate，不建立 SQLite 資料庫、不實作案件輸入、取名或 PDF 匯出。

## 實作與驗證結果

已完成單一 WPF 桌面專案與 solution。SDK 選擇由 global.json 定義，NuGet 依賴由 csproj 與 packages.lock.json 管理；沒有建立空的服務、測試或資料存取專案。

| 檢查 | 實際結果 |
| --- | --- |
| NuGet 一般還原及 locked-mode 還原 | 均成功 |
| 桌面專案建置 | 成功，零警告、零錯誤 |
| 正常啟動 | 實際開啟 WPF 視窗，WebView2 顯示本機 HTML／CSS，狀態為「本機預覽已就緒」 |
| 正常關閉 | 透過視窗關閉，程式結束碼為 0 |
| 預覽檔案缺漏 | 僅暫時改名建置輸出中的 preview.html；視窗顯示「找不到本機預覽頁」與修復提示，仍可關閉，結束碼為 0 |
| 恢復後重新開啟 | 恢復建置產物，重新開啟後 HTML 文字與正常狀態均再次確認 |
| 程式碼審查 | 獨立唯讀審查未發現需要修正的骨架正確性或資源生命週期問題 |

WebView2 使用者資料置於 `%LOCALAPPDATA%\OnlyFate\WebView2`。原始研究檔案與 Mockup 沒有因初始化而改寫。

操作入口以 [桌面專案 README](../src/OnlyFate.Desktop/README.md) 為準。本輪採建置及有限的實際介面驗證，沒有新增自動化 E2E 測試架構。未在缺少 WebView2 Runtime 的環境實測，也尚未驗證安裝包、PDF 匯出或正式報告版面。
