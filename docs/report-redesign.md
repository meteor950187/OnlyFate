# 報告與可搭配字池改版

## 目標與設計決定

依本輪使用者完整目標：兩組方案，每組兩個4–5字池、1主推+4替代示例、逐字說明與所有交叉配對驗證。舊的單張配對表不符合新需求，將改正常契約，不做只供樣本的分支。

UI/HTML設計採安靜的編輯式版型：米白底、深墨字、暖金細線；大字姓名與充足留白，兩方案有編號與分別的重點色。首頁做選擇摘要，每組以推薦/搭配和逐字卡片展開，不固定兩頁。PDF用A4明確章節分頁，HTML以螢幕寬度自適應卡片；同一ReportData。

字池由程式從完整合法配對中建立完整二分圖；模型只選通過計算的方案與推薦/示例，不負責把不合法字池變合法。每組兩位置分別同筆畫；兩組可使用不同筆畫配置。跨組最多重複2個不同字，且不得只交換同一套字。跨組混搭不自動允許。

字庫保存讀音、本義、祝願引申、風格、注意事項與逐項來源。康熙筆畫、臺灣讀音、字義分別核實；字五行來自明確選用的外部命名分類，衝突記錄，不冒充字典科學事實。缺資料停，不改硬限制湊數。

必用字與4–5字自由字池可能不相容：每個完整姓名都必須符合必用字，無法湊足完整字池時提供明確原因，不豁免必用字。

正式資格仍false，無OpenAI憑證則假transport與離線示範，不偽稱模型品質驗證。

## 執行計畫

1. 字庫研究與擴充：resources/naming 新版資料、來源紀錄；優先確認林姓土金下9+16/10+15/13+10配置可用，選自然可讀的字，不強制採用任何未核實字。逐字資料足以支持兩組互異字池。
2. 生成核心：NamingEngine/NamingContract/Step4Service 改兩組完整字池；ReportContract/Step5Service/ReportDataAssembler 同步2組各5示例、逐字資料；DemoWorkspace與測試共用契約。版本升級，舊版本明確失效而非例外崩潰。正常三次LLM，各最多一次repair。
3. 版型與桌面：ReportHtmlRenderer重做響應式/印刷設計，MainWindow展示組別與字池。實際GUI匯出HTML/PDF，多頁視覺修正直到可讀。
4. 全流程審查：Step1–6、context、hard constraints、來源競爭/失效、失敗取消與重開；修正發現問題，發行及文件，逐項完成稽核。

## 驗證

字庫來源覆蓋、所有組內笛卡兒積、交叉同音/重字/避諱/必用字、不同組重複限制、不足兩組拒絕、repair後仍不符停止；schema資料版本相容性、普通流程假transport走Step3–6、PDF/HTML同資料與hash；實際HTML響應式與PDF逐頁觀察；保留既有上游測試。

## 執行約束

使用者已授權設計與實作取捨，不再另等計畫批准。沿用當前checkout；repo無初始commit，採完整before檔案快照及檔案diff審查，禁止為方便流程擅自提交既有研究檔。
## 視覺驗收基準（本輪，取代舊Mockup）

- 字體：姓名與章節採 Noto Serif TC（本機已裝），內文 Noto Sans TC／Microsoft JhengHei；無遠端字型。名稱視覺32–42pt，內文至少10–11pt，字義卡標題22–28pt。其他電腦用可讀fallback，不隨附未處理授權的字型。
- 色彩：紙白#FCFAF6、墨綠#173F36、暖金#AA8859、細線#DDD8CD；第二方案可用低彩度靛青，但文字對比不能太淡。
- 預計閱讀節奏：總覽（兩主推對照、出生資料與使用方法）→方案一選擇/搭配→方案一逐字→方案二選擇/搭配→方案二逐字。實際頁數按內容調整，不強塞兩頁。
- 逐字卡：大字＋注音；標籤「本義」「放進名字」「風格／留意」。每字清楚直觀，避免名首/名末抽象欄頭取代字本身。
- 配字：兩個明確字池，使用「名字第一個字」「名字第二個字」，說明本組任選一字可配；1主推＋4替代不同層級，避免把16種全列為同等推薦造成負擔。
- 五格/三才可收在各方案底部的小型依據區，用實算值，但避免「本版程式已通過」等開發話語。
- 螢幕最大內容寬1000px左右，窄畫面單欄、正常桌面兩欄；不把A4縮成小字塞在WebView。
- PDF分頁尊重卡片與章節。長profile/5+5字池必須自然多頁，沒有裁切或孤單標題。頁邊短頁尾與頁碼不侵入正文。
