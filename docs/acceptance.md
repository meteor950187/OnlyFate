## 先看成品

1. 開啟 [OnlyFate.Desktop.exe](../output/app/OnlyFate.Desktop.exe)。保留整個 `output/app` 資料夾；本機已具備執行依賴，其他電腦需求見 [桌面 README](../src/OnlyFate.Desktop/README.md)。
2. 按右下角「開啟離線示範」，會另開獨立示範視窗。沒有 API 費用，不會新增正常案件。
3. 「報告預覽」可以看主推姓名、配對與依據，並另存 HTML／PDF。更新程式後，按右下角「建立新示範案例」看新版；既有報告與產物不會覆寫。舊版資料不能只改版本號來繞過版型檢查。
4. 在案件清單雙擊可重開；「request 與執行紀錄」查看預備送出的 request 與執行摘要；各階段結果另在對應頁籤顯示。離線樣本沒有模型呼叫，usage 顯示未知，不填造 token。

v11 PDF曾以產品相同的WebView2原生設定實印並逐頁驗收。本輪v12由產品`ReportArtifactService`、`ReportHtmlRenderer`及隔離`DemoWorkspace`產生HTML，在背景Edge驗證螢幕閱讀，並用相同背景列印環境比對v11與v12。未操作桌面、未重做WPF／WebView2原生互動驗收；實測範圍見下方v12紀錄。兩種呈現省略相近的wish，原始資料仍完整保存。

林姓樣本提供「寬厚有志」「溫潤開朗」兩組，各 4×4 字池、1 主推與 4 個示例，共 16 個不同候選字、32 種通過規則的組內搭配。跨組未驗證，不可任意混搭。字卡直接以字為標題，分開讀音、本義、放進名字的祝願、風格與留意事項。

若某一格式的內部檔案損壞，另一格式仍可使用。「重建報告檔案（不呼叫 AI）」從已保存資料新增報告版本，保留原紀錄；案件或上游已失效時，不能用重建跳過檢查。

## 試跑真實 API

在正常視窗建立並儲存案件，完成出生城市確認與排盤後，在「AI 試行判讀」填模型 ID／API key，再依序進行判讀、取名配置、報告生成。模型須支援 Responses API 的 strict JSON schema；不擅自指定尚未測過的預設模型。

每個階段可先查看 request，只有按下執行才呼叫模型。key 留在程序記憶體，可清除，不保存到 DB。正常三次呼叫、各最多一次修正；詳見 [AI context 與呼叫流程](ai-call-flow.md)。

**目前不能拿任意姓氏當成已支援。** 研究字庫以林姓與少量候選字為主；缺少姓氏筆畫、指定字或同音資料時會停止。備註無法採用的內容可忽略並記錄理由，不能跳過硬性避諱／必用字限制。
