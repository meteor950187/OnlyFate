# 本機完整流程實作計畫

> 執行方式：superpowers:subagent-driven-development；依工作逐段實作、測試、審查。使用者已授權持續完成及桌面驗收。

**目標：** 可從案件、排盤、AI 判讀一路產出可重新開啟的取名配置、HTML 與 PDF，供完整驗收。

**規格依據：** AGENTS.md、Step 1–3、既有林姓案例及精簡 PDF Mockup。仍未驗證的命理方法不能偽裝為正式品質認證。

**技術：** 延續 WPF／WebView2、SQLite、OpenAI Responses，固定資料與版型產出 HTML，WebView2 列印同一份 HTML 為 PDF。

## 共通限制

- 單姓、雙字名、國語；可追溯的有限字庫，未知字或讀音不猜。字五行為試行分類，與筆畫三才分開。
- 不改寫 migration 001；保持版本快照、交易一致性、取消、有限重試、API key 不入庫。
- 不引入備註整理呼叫；Step 3 首次呼叫，Step 4 只在已檢查候選中選擇，Step 5 撰寫短文；每階段獨立 context。
- 程式檢查不等於命理方法驗證。目前提供明示試行的驗收交付品，正式交付資格維持 false。
- 最多三個主推配置；所有列出的配對必須逐一通過限制，不能讓使用者任意互換未驗證字。
- 不含人生保證、健康財運斷言；結果優先、短句、少量主推。

## 工作

1. **配置與組名核心**：升級 Step 3 加結構化選字元素；有限來源字庫；五格／三才計算、禁字／同音／指定位置檢查；Step 4 AI 選擇、短理由、最多一次修正；明確區別正式禁止與可供驗收試行；版本失效與重開測試。
2. **報告與產物核心**：Step 5 有限 AI 文案、驗證候選 ID 與短文、固定事實由程式合成；NamingReport、ReportArtifact 寫入與 hash／路徑檢查；共用 HTML 版型，PDF 完成才登記成功；快照失效、惡意 HTML、檔案失敗測試。
3. **桌面串接與驗收**：Step 4–6 操作、context／紀錄查看、重開恢復、取消、PAGE/PDF 匯出；提供清楚標示的離線虛構驗收案例，不冒充真正 API 結果；實際桌面及 PDF 驗證。
4. **整體整理**：全套測試、獨立審查、修正、文件單一權威、明日操作路徑與尚需驗證的邊界。

## 驗收重點

- 改案件、重排或重判讀後，舊的下游結果不能被當成目前結果。
- 未知姓氏／字音／指定字有明確說明；零候選不放寬硬性條件。
- API 拒絕、超時、格式不符與取消，不留下假成功或持續 running。
- HTML 編碼、CSP、輸出目錄限制；預覽與 PDF 使用同一份內容。
- 沒有真實憑證時驗證傳輸契約及模擬回應，不能宣稱已完成真實 OpenAI 品質測試。
